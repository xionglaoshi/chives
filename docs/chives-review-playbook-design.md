# 短线复盘与次日预案：Chives 支持方案（设计稿，待用户确认后再派任务）

来源：`A股短线复盘与次日操作预案.pdf`（每日节奏：15:00–19:45 收数 → 20:00 唯一一次正式复盘 → 次日 08:30–09:25 盘前核对 → 09:25–15:00 盘中条件式指导 → 收盘后记录归档）。

## 1. 总原则（落到产品里的几条硬规则）
1. **状态由程序判定，文字由智能体写**：预案条件是否触发、候选股处于"观察/等待确认/按预案执行/放弃/按计划退出"哪一档，都由 hub 用确定性规则算；智能体只负责复盘叙述、选候选、写条件。这样盘中不依赖模型、不会临场改口。
2. **预案盘后写好、盘前只能收紧**：09:25 后预案锁定；之后只允许取消/降级/收紧止损，不允许放宽放弃条件或风险边界（文档第 04、05 节"不得临时把放弃条件改成买入理由"）。
3. **缺数据写"待确认"，不推测补齐**：每份复盘带"数据截点 19:45 + 来源 + 缺失项"页眉（与我们现有"不编"原则一致）。
4. **不下单、不连券商**：预案只提醒；"执行记录"由用户自己录入，或由持仓前后快照差异推断后请用户确认。
5. **阈值归用户**：文档第 06 节明说仓位/回撤/暂停阈值要个人设定并回测验证。Chives 不内置"通用百分比"，让用户在画像里填，没填就只显示"未设置"，不触发硬提醒。
6. 文档"不提供具体个股买卖指令"的免责口径，与你之前要求的"可以给观点/价位，不加免责"不冲突：预案本质是**条件式**表达（"若…则观察/放弃"），我们沿用这个形式，不使用"买入名单"措辞。

## 3. 架构

### 3.1 数据层（market-watch v1.4）
- `GET /pool?date=` 涨停池明细（代码、名称、连板数、首封时间、炸板次数、封单资金、换手、行业、题材标签）、`/pool/ladder` 梯队、`/pool/history?days=20`（数量、封板率、1进2/2进3 晋级率）。
- `GET /themes` 概念/题材榜；`GET /breadth/series` 盘中涨跌家数序列；`GET /yesterday` 昨日涨停今日表现（开盘溢价、盘中最高、收盘）。
- 盘后 15:05 起落库；首次启动按日期回补近 30 个交易日（东财池接口支持日期参数），让晋级率、趋势图第一天就有数。
- 口径差异：每个接口带 `definition` 与来源（文档强调不同平台封板率口径不同，必须标明）。

### 3.2 hub v1.1
- **作战卡（Plan v2）**：`conditions` 数组，每条带类型——`market`（环境标签、指数条件）、`sector`（板块涨幅/排名/涨停家数）、`stock`（价位区间/放量/竞价强弱）、`giveup`（板块转弱、竞价偏离、承接不足、失效位）；`risk`：单笔可承受亏损、止损价、仓位上限、预设退出条件；`state`：观察/等待确认/按预案执行/放弃/按计划退出（程序判定）；`locked_at`（09:25 锁定）。兼容现有单条件 Plan。
- **候选池**：每晚 ≤5 只，每只绑定作战卡；盘后自动补"次日开盘溢价/最高/收盘/条件是否触发"。
- **复盘记录**：每日一份结构化 JSON（环境标签+证据、主线/次线、梯队、龙虎榜、事件日历、昨日反馈、候选池、数据页眉与"待确认"清单）+ 智能体正文。
- **指引卡**：09:30/10:00/11:30/13:00/14:30 定点生成，统一格式（时间与数据时间戳、市场状态、题材状态、候选状态、当前动作、下一检查点与风险边界）；内容由程序拼装，不调模型。
- **应急检测（确定性）**：指数快速下跌、跌停扩散、持仓跌停/停牌/重大公告 → L3 "应急卡"，内容就是文档的触发链（暂停新增风险→核实→查组合敞口→按既定规则→记录）；阈值来自用户设置。
- **纪律**：心理状态记录、连亏/日回撤暂停标志（暂停期间新建/确认作战卡时给醒目警告，用户可覆盖，不硬拦）。
- 内部定时：15:05 落库、19:45 数据截点标记、09:25 锁定，均为 hub 内部确定性任务，不占模型额度。

### 3.3 智能体层
- 新 skills：`daily-review`（20:00 流程：环境→题材/涨停池→龙虎榜→事件日历→昨日反馈→候选≤5）、`premarket-check`（08:30–09:25）、`battle-card`（写条件、算仓位）、`risk-boundary`（对照画像上限）。
- 子智能体复用现有角色：行情/环境分析、题材与涨停池分析、事件与公告研究、**复核员**（按 07 节 20:00 检查表逐项核对：数据日期/口径/来源/待确认/事件日历/预案写明触发与放弃）。
- hub-mcp 增工具：`hub_get_review_data`（一次拿齐当日池/梯队/题材/环境/昨日反馈）、`hub_save_review`、`hub_propose_battle_card`（仍是 proposed，需用户确认）、`hub_list_candidates`。
- 运行：新增 `review-runner`（仿现有盯盘触发器的无头运行方式）：**20:00 一次复盘、08:30 一次盘前核对**，每日 2 次模型调用，与盯盘分析的 10 次/日额度分开记；晚间 19:45 后出现新重大公告只标"预案失效/待重评"，不重做复盘。

### 3.4 界面（我来做）
- 新页「复盘」（侧栏：我的 / 盯盘 / **复盘** / 定时任务）：顶部数据页眉与环境标签；8 张图（沿用现有图表件，涨停梯队用分层方块）；候选池与作战卡（条件逐条亮灯，状态五档）；次日时间线；历史复盘可翻。
- 盯盘页加"盘中指引"条与应急卡；「我的」页加仓位余量（总/单票/题材集中度/单笔风险）与心理状态录入、暂停标志。
- 候选与记录统计：按环境/题材/连板高度分组，样本不足明说。

## 5. 风险与待你定的事
1. **数据**：东财池/概念榜无官方保证，口径随平台不同（文档也提醒）；竞价（09:15–09:25）逐笔数据暂无稳定免费源，盘前核对先用 09:25 的开盘价/成交量，竞价细节标"待确认"。龙虎榜与宏观事件日历同理。
2. **额度**：每日多 2 次模型调用，复盘那次会较长（多工具、多子智能体）。
3. **范围**：该文档偏"涨停/接力"短线。我们只把涨停股放进观察池，不做自动打板，也不出买入名单。
4. **需要你确认**：
   - 是否新增第三个页面「复盘」（建议是）；
   - 20:00 / 08:30 自动运行是否同意（也可只在你点"开始复盘"时运行）；
   - 仓位上限、单笔风险、连亏/回撤暂停阈值你来填（我给"问答式设置"，没填则不触发硬提醒）；
   - 心理状态记录只存本机，是否需要；
   - 先做 P1 还是先看一版「复盘」页的原型图再定。

## 6. 用户决策与方案调整（2026-11-04，覆盖前文冲突处）

1. **先补数据（P1）**：同意，立刻开工。
2. **新增「复盘」页**：同意。侧栏顺序：我的 / 盯盘 / 复盘 / 定时任务。
3. **复盘用 dsh 定时任务来做，不另写运行器**（取消 §3.3 的 `review-runner`）：
   - 两个任务：工作日 20:00 复盘、工作日 08:30 盘前核对（`Asia/Shanghai`，RRULE，`target: new` 每次新开会话，会话标题统一前缀"[复盘]"）。创建由智能体用 `schedule_create` 完成，**创建前向用户展示任务内容并得到明确同意**（「复盘」页的"开启复盘定时任务"按钮只往对话里填指令，不直接创建）。
   - dsh 的日程**没有交易日历**：任务提示词第一步固定调用 hub 的交易日判断（`trading_day:false` → 回复"今日休市，不复盘"并结束）。
   - **Host 不在线就不触发**（重启后只补最近一次）：「复盘」页显示"今日复盘未执行"并提供"现在补跑"（填指令）。
   - 日程投递不保存正文：智能体复盘结束必须调用 `hub_save_review` 写入结构化结果，「复盘」页读 hub，不翻会话。
4. **阈值由智能体建议、人来调整**（执行方案、总仓位上限、单票上限、题材集中度、单笔风险预算、暂停线）：
   - hub 设置表每项带 `value`、`source: agent_suggested | user_set | unset`、`basis`（依据）、`backtested:false`（明示未经回测）、`suggested_at`。智能体依据持仓、波动、画像、近期复盘给建议（`hub_suggest_settings`）。
   - 建议**不自动生效**，状态"建议中"；用户在「复盘」页"纪律与仓位"卡点"采纳"或直接改数字（改了即 `user_set`）；未采纳的项不触发硬提醒。每项都有"让 Chives 重新建议"。
   - **"连亏暂停"先不按交易笔数统计**（无券商对接，系统不知道逐笔盈亏）：第一版暂停线用 ① 当日回撤（总资产快照）② 持仓累计浮亏比例 ③ 用户在页面手动记录的连亏笔数。"由前后持仓快照差异推断卖出并请用户确认"放到后续。
5. **盘中沿用现有盯盘逻辑**：作战卡条件由 hub 评估（现有计划/信号评估通道），**条件到达 → 触发智能体快速判断**：
   - **触发源**：hub 新增 `GET /triggers?since_id=`（作战卡状态跃迁：确认条件到达、放弃条件命中、板块/环境条件变化、应急触发）。**状态跃迁去抖**：只在状态真正变化时触发一次，条件在阈值附近来回抖动需滞回，每张卡每个跃迁方向有独立冷却。
   - **独立队列**：快速判断**不得与深度分析共用队列**（深度分析最长 13 分钟会堵死买点）。新增独立的快速运行器（同一触发器包内独立实例或独立进程），单独日额度（默认 20 次/日）、冷却与超时（120 秒）；深度分析仍 10 次/日、780 秒。
   - **条件先亮灯、判断后补上**：条件到达由程序瞬间判定并立即在卡片上亮灯 + 推送信号；"Chives 判断"在稍后（约 20–60 秒）补写进同一张卡。**程序判定的状态为准，智能体判断只是补充意见：不能改条件、不能放宽放弃线。**
   - **提前给上下文（hub 在触发瞬间组装 context pack）**：作战卡全文（条件、放弃条件、风险边界、按风险预算算出的仓位）；最近一次复盘摘要（环境标签与证据、主线、入选理由）；当前快照（现价、涨跌幅、VWAP 偏离、距涨跌停、所属板块排名与涨幅、市场宽度与环境标签）；与持仓的关系（是否已持有、占比 vs 单票上限、总仓位余量）；纪律状态（是否暂停、今日触发次数）；已采纳的阈值；触发条件与触发时刻。
   - **快速判断提示词 `fast-judge.md`**：数据已在上下文里，**最多 2 次工具调用**（刷新报价、必要时看一条公告），不做长篇研究；固定输出 `动作（观察/等待确认/按预案执行/放弃/按计划退出）｜一句话理由（≤40 字）｜下一检查点｜风险边界`，总长 ≤150 字；结果写回作战卡与信号卡，卡片显示"Chives 判断"。可选配更快的模型。
6. **数据（P1）两点验证**：东财涨停池按日期回补 30 个交易日是否可用，由 T104 实测并如实报告；不可用的日期标"无数据"，趋势从启用日起累积，不编。题材涨停数暂用行业口径并在界面标注"行业口径"。
7. 修订后的分期：P1 数据（T104）→ P2 hub（设置、作战卡、复盘存储、triggers、context pack、纪律）→ P3 智能体（hub-mcp v2、复盘与盘前 skill、快速判断提示词与独立运行器、定时任务模板）→ P4「复盘」页（我做）→ P5 影子运行一周。

## 7. 修订（2026-11-04 晚）：盘中只保留一套评估逻辑

用户明确：**盘中复用同一套盯盘逻辑；盯盘逻辑不够就增强它，不另起一套；以后盘中的能力都增强这块。**
