# 主升浪策略 bot 方案（草案）

> 依据：用户提供的《首板观察池与主升浪阶段回测规则》说明文档与规则总表（2026-11-17）。本文是方案，不是已验证的策略；规则未冻结前不写代码。

## 1. 策略结构（按原文整理）

```
全 A 日线 ──► 首板识别（当日收盘涨停 + 前 10 日无涨停 + 前 10 日收盘回撤 3%–15% 且低点后有反弹）
                │
       ┌────────┴─────────┐
  次日收盘涨停          次日未涨停
  （二板）               │
   │                首板观察池（最长 45 个交易日，停牌占日）
   │                 ├─ 支撑监控：黄金坑低点 / 首板日最低价，跌破后 3 日收复，否则移出
   │                 ├─ 突破标记：收盘 > 首板日起至前一日最高收盘 → 固定标记价
   │                 │    ├─ 2 日内涨停 → 优先级一
   │                 │    ├─ 2 日连续收盘 > 标记价 → 优先级二
   │                 │    └─ 否则再看 3 日，收回 → 普通观察级；未收回 → 移出
   │                 └─ 普通观察级评分：支撑 30% + 均线收拢 15% + 时效 45% + 量能 10%
   ▼                      │（触发启动标记）
主升浪阶段池 ◄────────────┘
  ├─ 分数 = 涨幅基础分（<15%:80，15–25%:100，>25% 每 5 个百分点 −10）− 回撤扣分（每完整 3% −10）
  ├─ 每日收盘按分数排序，同分最近启动优先，0 分仍留池
  └─ 移出：入池后第 1、2 次收盘跌破 MA10 各观察 3 日可修复；第 3 次跌破立即移出
```

本质上是一个**纯日线、收盘后确定性计算**的状态机，两个池共 5 类事件状态（入池、支撑破位/收复、突破标记/确认、主升浪评分、MA10 计数）。它适合写成**代码引擎**，由 bot 负责解读、复核、汇报和问答，而不是让模型每天自己算。

## 2. 需要确认的规则歧义

原文"尚未确认"4 项之外，我逐条推演时还发现 7 处会影响结果的歧义：

| # | 位置 | 歧义 | 建议口径 |
|---|---|---|---|
| 1 | 入池·回撤 | "前 10 日收盘价回撤 3%–15%"从哪里算到哪里 | 窗口内最高收盘到其后最低收盘：`(maxC − minC_after)/maxC` |
| 2 | 入池·低点 | "最低收盘价之后至少一天收盘高于低点"——低点若在首板前一日则不满足？ | 是，低点不能是首板前一日 |
| 3 | 启动 vs 突破标记 | 第一节"启动"与第三节"突破标记"是否同一事件 | 同一事件：收盘 > 首板日起至前一日的最高收盘（含首板日收盘） |
| 4 | 突破后去向 | 第一节说启动即进主升浪池、不再受 45 日约束；第三节说未确认且 3 日未收回则"移出"——移出的是首板池还是两个池都移出？ | 只影响首板池的优先级与排序；主升浪池只按 MA10 规则移出 |
| 5 | 支撑监控 | 启动后是否继续监控两个支撑 | 启动后停止，改由 MA10 规则管理 |
| 6 | 排除项 | "第 20–30 日曾满足均线收拢，总分下限 60"叫"排除项"但实际是保底 | 按保底处理，确认命名 |
| 7 | 涨停识别 | 涨跌幅限制随板块与时间变化（主板 10%、创业板 2020-08-24 起 20%、科创 20%、ST 5%、新股前 5 日无限制、北交所 30%）；历史 ST 身份无现成数据 | 用未复权价按当日规则计算涨停价判定；股票池默认排除 ST/*ST、北交所、上市不足 60 个交易日的次新；ST 身份按名称历史近似并在报告标注 |

原文"尚未确认"的建议口径：
- **时效分**：首板后第 k 个交易日（k=1…45）得分 `100 − (k−1) × 100/44`，保留两位小数参与加权。
- **>25% 分档**：`(25,30]` 90、`(30,35]` 80……每 5 个百分点一档，`(70,75]` 及以上 0 分；边界值归入较低涨幅档。
- **买卖与费用**（第二阶段收益评估用）：优先级一/二或启动标记次日开盘买入，一字涨停买不到则放弃；主升浪池移出次日开盘卖出；佣金万 2.5（最低 5 元）、卖出印花税 0.05%、滑点 0.1%。
- **连板池监控**：第一版不做，二板票只进主升浪池。

## 3. 数据：现状与缺口

| 需要 | 现状 | 方案 |
|---|---|---|
| 全 A 历史日线（未复权 + 前复权 + 成交量） | 网关 `market_bars` 能按只取，2019 年起可取；没有全市场本地库 | 新建本地日线库（SQLite，标准库即可）：首次回填约 5,000 只 × 2019 年至今，按限频分批约 1 小时；之后每日 15:30 后增量 |
| 历史涨停池 | `market_limit_pool` 只到约 1 个月前 | 不依赖，用未复权收盘价 + 当日涨跌停规则计算；近期与涨停池交叉核对 |
| 交易日历与停牌 | 有交易日历；停牌 = 交易日里该股无 K 线 | 直接用 |
| ST 身份、上市日期 | 上市日期可取；历史 ST 无现成数据 | 名称前缀近似 + 报告标注 |
| 除权除息 | 前复权由源给出 | 每日增量时检测复权因子变化，变化则重算该股前复权序列 |

## 4. 系统设计

```
packages/surge-engine（Python，确定性）
  ├─ store：日线库、交易日历、涨跌停规则、数据质量检查
  ├─ rules：首板识别 / 支撑 / 突破确认 / 评分 / 主升浪 / MA10，每条规则一个纯函数
  ├─ replay：按日推进状态机（只用当日及之前的数据），回测与实盘同一套代码
  ├─ outputs：逐事件记录、每日池快照、K 线标注图
  └─ daemon + MCP：surge_pools(date)、surge_stock(code)、surge_events(...)、surge_backtest(...)
Chives
  ├─ 新 bot「主升浪」：persona + skill（规则解读、复核清单、回测报告写法）
  ├─ 右侧面板 `surge`：首板池（优先级一/二/普通，带分数）与主升浪池（分数、MA10 计数）
  ├─ 定时任务：交易日 15:45 跑当日池 → bot 写盘后简报；新进优先级一、主升浪池移出时提醒
  └─ 盯盘：把突破线、支撑位、MA10 交给盯盘，盘中到价唤醒 bot（不下单）
```

原则：
- 规则只在引擎里实现一次，bot 不自己算分。
- 每条事件可追溯到具体 K 线与数值。
- 任何输出不使用未来数据。

## 5. 分阶段

| 阶段 | 内容 | 产出 | 验收 |
|---|---|---|---|
| P0 规则冻结 | 第 2 节歧义逐条确认，写成形式化规格 + 手算样例 | `docs/strategy/zhushenglang-spec.md` v1 | 你确认 |
| P1 数据层 | 日线库、回填、增量、涨停判定、质量检查 | 全 A 2019 年至今日线 | 近 1 个月涨停判定与涨停池一致率 ≥ 99% |
| P2 规则引擎与事件回放 | 状态机、逐事件记录、每日池快照、K 线标注 | 历史事件库 + 抽样标注图 | 每条规则有手造 K 线单测；你抽 20 只人工复核 |
| P3 bot 与界面 | 主升浪 bot、MCP、面板、盘后任务、提醒、盯盘联动 | 可用的 bot | 实盘跑 5 个交易日对照 |
| P4 收益评估 | 买卖与费用模拟、分年度/分市场环境统计、参数敏感性 | 回测报告 | 按原文要求：先事件、后收益，不用未来涨幅筛选 |

P1 与 P0 可并行。P2 依赖规则冻结。P3 可以在 P2 出数据后开始。
