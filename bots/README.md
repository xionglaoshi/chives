# Chives Bot 名册

| Bot | 岗位 | 主要职责 |
| --- | --- | --- |
| [总经理](ceo/bot.yaml) | 总经理、默认入口 | 回答「问 AI」与一般问题，处理附件，协调已聘员工并汇总交付 |
| [个股研究员](analyst/bot.yaml) | 个股研究员 | 研究持仓及关注公司，解读财报、公告和估值 |
| [盯盘交易员](trader/bot.yaml) | 盯盘交易员 | 跟踪持股，独占盯盘任务管理，复核量化信号及策略回测 |
| [风控总监](cro/bot.yaml) | 风控总监 | 根据持仓与关注发现组合风险和公司风险 |
| [投研总监](cio/bot.yaml) | 投研总监 | 研究宏观、海内外市场、行业和榜单，筛选投资机会 |

开发者在 `bots/<id>/bot.yaml` 和对应的人设文件中维护岗位、技能、授权、模型及默认头像。用户在网页「Bot 市场」或终端「聘用管理」启用与停用可选员工，也可通过档案头像右下角的图标更换显示头像。总经理为常驻员工，工作目录是 `~/.chives/workspace/bots/ceo`。

开发者在岗位名册的 `accepts_handoffs` 声明该员工承办的事项，每类事项登记一个岗位，名册把可承办事项与聘用状态一起提供给所有员工。客户可以在任一岗位会话提出委托。员工通过岗位名册找到承接人，把客户原话和交接说明一同发送。原会话显示受理状态、承接会话及已建立的盯盘任务入口。未聘用的岗位保留交接草稿，聘用后继续办理。盯盘创建、编辑、暂停、恢复和删除归盯盘交易员，客户也可通过设置管理自己的任务。升级时未到期的旧活动盯盘移交盯盘交易员，保留任务 ID、条件、到期时间和历史记录。存在这类任务时沿用其在岗状态，保证既有盯盘继续运行。历史会话维持原归属。

交易员受聘后，已授权读取的每只持仓会自动建立技术盯盘。点名与持仓可以共用同一项监测。清仓后继续保留客户点名的证券。客户暂停或删除的任务保留其选择。可用指标、数据覆盖和触发规则见[技术盯盘说明](../skills/technical-signals/SKILL.md)。

A 股交易日北京时间 08:30 由投研总监发送盘前简报，16:30 由风控总监发送复盘简报。两岗分别查找机会和风险，读取按岗位授权的持仓、关注、短期记忆证券、已发布榜单和带时点的新闻。客户可在设置中调整时间、暂停或删除任务，重新聘用时沿用其选择。总经理接待、协调及汇总，个股研究员承担公司研究和估值。开发者分别维护[公共规则](_shared/rules.md)、各岗位的 `persona.md`、技能与工具范围。

### 对话右侧工作台

各 Bot 在自己的 `bot.yaml` 使用 `workbench` 列出模块。当前支持 `identity`（身份卡）、`tasks`（现有任务）、`activity`（动态）。标题可单独配置。模块按名册中的顺序显示，身份卡在第一位时固定在顶部。新增 Bot 省略该配置时使用上述默认次序。修改已有 Bot 的工作台时编辑其名册。需要新模块时，在网页工作台实现模块后，仅给需要它的 Bot 声明。折叠与宽度均按 Bot ID 在当前浏览器保存。

动态的普通答复以原会话任务标题展示，点击定位原消息并保存已读。提醒沿用通知的已读状态。已启用定时任务和生效盯盘通过现有任务接口读取。
