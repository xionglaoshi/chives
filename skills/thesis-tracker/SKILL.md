# A 股投资逻辑跟踪（thesis-tracker）

每次更新给**两个结论**：**公司逻辑**（生意是否按当初的判断走）与**股票判断**（今天是否值得行动）。两者会分叉：公司变好而股票变贵、公司变差但价格已反映。一个状态栏会把两种情况混成一个。

证据标签、来源分层、新鲜度与就绪姿态遵循 `research-conventions`。行业 KPI 与领先信号见 `references/sector-signals.md`（不在已覆盖行业时读）。

## 边界

- 只做研究，不下单、不给具体买卖数量；仓位建议交 `risk-boundary`，交易方案交 `trade-pitch`。
- **台账只追加**：旧支柱、旧阈值、旧证据行保持原文；失效的标 `superseded`/`stale` 并写日期，新结论另起一行。漂移只有在没被改写的旧记录面前才看得出来。
- 每个数字带报告期/数据日期；取不到写“取不到”，不用估计值补。
- 一致预期是卖方汇总，不是事实；公司公告原文 > 交易所/巨潮 > 数据工具 > 媒体。

## 第 1 步：定模式，写清逻辑与支柱

模式由用户给的材料决定，默认不要追问：

| 用户给了 | 模式 | 默认动作 |
|---|---|---|
| 什么都没给 | 空白模板 | 输出空结构 + 最少输入清单，不填数 |
| 只给代码 | 建框架 | 从公告、财报、一致预期起草 3–5 条候选支柱，标 `draft` |
| 已有逻辑 | 载入 | 拆成支柱记录，缺失字段标 `missing` |
| 逻辑 + 新事件 | 更新 | 只处理增量 |
| 财报/公告 | 财报后 | 先做第 2 步的证据质量拆解 |
| 多只持仓 | 组合复盘 | 逐只给两个结论，再给优先级与恶化名单 |
| 多空配对 | 配对 | 每腿各一份，加“什么会拆掉配对” |

3–5 条支柱，每条一句话且**能被证据杀死**。“长期空间大”不是支柱。

每条支柱带这些字段：

| 字段 | 内容 |
|---|---|
| 主张 | 一句可证伪的话 |
| 优先级 | `core`（决定结论）或 `supporting` |
| 基准值 | 建仓/首次覆盖时的数字与日期 |
| 预期路径 | 该指标到什么时候走到哪 |
| 确认/警示/破坏阈值 | 三档，各带来源；破坏阈值就是退出触发 |
| 最新证据 | 第 2 步台账行号与日期 |
| 信号 | 第 2 步的方向词 |
| 证据质量 | `fact` / `company claim` / `street estimate` / `model-derived` / `judgement` / `assumption` |
| 来源状态 | `inherited`（原逻辑就有）/ `draft`（我们提的，待用户确认）/ `approved`（用户确认的监控规则） |
| 模型落点 | 对应哪个报表科目或估值输入，破坏时知道改哪里 |
| 隐含动作 | 破坏后是“重写/减仓/观察/退出” |
| 下一个验证点 | 有日期的披露或事件 |
| 负责人 | 谁跟进（无则写“用户”） |

**空白模板**：只给结构和最少输入清单（代码、方向、期限、2–3 条主张、已有阈值），不凭记忆填任何数。

**完成判据**：模式写明；每条支柱 13 个字段齐全或明确标 `missing`；无来源的数字不出现。

## 第 2 步：追加证据台账

一行一个数据点，只追加不改写：

| 字段 | 内容 |
|---|---|
| 行号与日期 | 稳定 id；事实到达日期 |
| 报告期 | 该事实所属报告期（YYYY-03-31 等） |
| 来源与类型 | 公告/财报/工具/新闻，附证据标签 |
| 事实 | 原文数字，带单位 |
| 我们此前的预期 | 模型或判断里的数 |
| 市场预期 | 一致预期或业绩预告区间，带抓取日期与机构数 |
| 解读 | 一句话：对哪条主张意味着什么 |
| 支柱 | 落在哪条支柱 |
| 信号与幅度 | 明显确认/确认/弱确认/中性/弱化/恶化/明显恶化；另可标 `mixed`、`invalidating`、`untested` |
| 证据质量 | 同上 |
| 影响 | 模型/估值/置信度/已采取动作 |
| 下一步与负责人 | 还差什么证据、谁跟进 |

**信号不求和**：不要加权成“置信度 72 分”；用方向词描述分布，再写一句结论。

**证据质量拆解（财报必做）**：营收超预期要拆量、价、结构、成本、税率、股本、汇兑、一次性项目、补贴、会计口径变化；说清是哪一项贡献了增长、是否会持续。靠税率和政府补助带来的超预期，不更新经营类支柱。

**管理层可信度**：可量化、与上季说法一致、讲清机制、承认问题的表述加分；空泛乐观、改 KPI 口径、选择性披露不加分。写明看到的是哪一种。

**财务红旗**（每条都降低对应支柱的证据质量，并开一个有日期的跟进项）：应收账款/存货增速持续高于营收、经营现金流与净利润背离、毛利率异常高于同业且无解释、在建工程/研发资本化突增、关联交易与资金占用、审计意见或财务总监变动、商誉减值、反复出现的“一次性”费用、政府补助占利润比重过高。

**完成判据**：每个新数据点是一行，指名支柱、信号、证据质量；旧行未改；每个动作都有输入。

## 第 3 步：给支柱定状态，再汇总

每条支柱只能取一个状态：

| 状态 | 含义 |
|---|---|
| `strengthening` | 证据好于预期路径，且前路不变或更好 |
| `intact` | 证据与预期路径一致 |
| `watch` | 触及警示阈值，或证据混合；等下一个验证点 |
| `impaired` | 破坏阈值被触及，但其他支柱仍支撑逻辑 |
| `broken` | 主张失败，持有理由消失 |
| `changed` | 生意做的已不是当初写的那件事 |
| `untested` | 自建仓/首次覆盖以来没有新证据 |
| `retired` | 主动关闭，写日期与原因 |

**汇总规则**（防漂移）：汇总跟随 `core` 支柱。一条 core `impaired` 而汇总比 `watch` 更乐观，必须写一句“用什么抵消、证据是什么”；两条及以上 core `impaired`，汇总即 `impaired`；任一 core `broken`/`changed`，汇总同状态。没有这条规则，汇总会在支柱烂掉一年后仍写 `intact`。

读者看到的记分卡：

| 支柱 | 优先级 | 预期路径 | 最新证据 | 信号 | 状态 |
|---|---|---|---|---|---|

**完成判据**：每条支柱一个状态；汇总有规则依据或抵消句；没有用户未定义的加权分数。

## 第 4 步：给股票判断

| 判断 | 成立条件 |
|---|---|
| `callable` | 动作所需的输入都在手（价格、估值锚、仓位/风险预算） |
| `conditional` | 只差一个具名输入；写清它和到达日期 |
| `re-underwrite` | 逻辑变了，回到 `stock-analysis`/`initiating-coverage` 重做，而不是微调 |
| `inputs missing` | 缺价格/估值/持仓中的一项或多项 |

**闸门**：没有当前价（`market_quote`）、没有估值锚（`company_valuation`）、没有风险预算（`risk-boundary` 或用户口述），就是 `inputs missing`，写明缺哪项。

**价格异动要拆**：把涨跌拆成基本面、预期修正、估值倍数、行业 beta、资金/筹码、政策、市场整体；能归因的写归因，不能的写“未归因”。不能归因的异动是问题，不是确认。

**完成判据**：股票判断取四值之一；非 `callable` 写明缺什么、由谁/何时补；引用的价格异动有拆解。

## 第 5 步：监控表与 KPI

| 指标 | 阈值 | 来源 | 窗口 | 确认信号 | 证伪信号 | 触发后动作 | 未触发动作 | 来源状态 |
|---|---|---|---|---|---|---|---|---|

A 股常用监控项：

- 财报：`company_financials` 的营收/归母/扣非/经营现金流；`company_earnings` 的预告与预约披露日。
- 估值：`company_valuation` 的 PE/PB 分位。
- 资金：`market_fund_flow` 主力净流入；`market_trading_activity(kind="margin")` 两融余额（T+1）。
- 筹码：`company_holders(kind="count")` 股东户数；`kind="lockup"` 未来解禁；`market_northbound(kind="holdings")` 季度持股。
- 事件：`company_announcements` 的重组、增发、股权激励、诉讼、风险提示。

KPI 表一行一个指标，六种比较基准都要在：

| KPI | 本期 | 上期 | 我们的预测 | 公司指引/预告 | 一致预期 | 阈值 | 同业 |
|---|---|---|---|---|---|---|---|

取不到的基准写 `n/a` 并在格内写原因，不删列。

**完成判据**：每个监控项都写了阈值两侧的动作；KPI 行六种基准齐全或标 `n/a` 及原因。

## 第 6 步：漂移与反方压力测试

每次更新逐条标“存在/不存在”：

1. **理由换了**：今天的持有理由不是建仓时的理由，且没有 `re-underwrite` 记录。
2. **催化洗白**：催化没兑现，用定性说法替换，而不是新的有日期验证点。
3. **估值替代**：当初买成长/毛利，现在只剩“便宜”。
4. **用期限打发**：反复出现的反证被说成“长期噪音”。
5. **防御变理由**：为上行买的仓位，现在用“跌得少”当持有理由。

再做反方：以反方持有者的口吻写最强反对意见、其证据、什么会证明它对了、什么会改变我们的判断、开放问题、下次复盘日期。可用的追问：争论的是增长、毛利、估值、资产负债表、治理还是政策？跟踪的 KPI 是领先还是滞后？走弱是周期、公司还是结构？当前价格已经假设了什么？

**完成判据**：五个漂移模式都标了存在/不存在；反方有具体观点与证据，不是稻草人。

## 第 7 步：运行方式与输出

先写运行方式，再写内容：

| 项目 | 值 |
|---|---|
| 决策人 | 用户 |
| 研究负责人 | 本 bot/分析者 |
| 证据台账负责人 | |
| 复盘频率 | 至少每季度，催化事件后即时 |
| 催化后更新时限 | 事件后 N 个工作日内 |
| 升级触发 | 破坏阈值触发、汇总 `impaired` 或更差、股票判断连续两次 `inputs missing` |
| 下次复盘日 | 日期与要做的决定 |

交付顺序：头部（汇总状态、股票判断、就绪姿态、数据时间）→ 运行方式 → 支柱记分卡 → KPI 表 → 监控表 → 本次新增台账 → 漂移与反方 → 下次复盘。Markdown 交付，路径遵守 T149 约定。

**完成判据**：第一屏有两个结论与姿态；台账增量列全；下次复盘有日期。

## 常见错误

- **只更新结论不改台账**：无法证明结论是怎么变的。
- **支柱不可证伪**：写成“赛道好”“管理层强”，永远 `intact`。
- **把股价下跌当逻辑破坏**：价格是观点，不是事实；先拆异动。
- **用一致预期当事实**：它是卖方汇总，带日期与机构数引用。
- **缺数据就跳过**：写 `n/a` 与原因，不删监控项。
