# 这张持仓表能承受什么

先确认用户问的是实际持仓、模拟盘还是拟买清单。用已获授权的 `portfolio_get` 读取实际数量，用 `portfolio_valuation` 取估值日、市值、现金和缺价标记。风险偏好、资金用途和用钱日期取自用户画像；当日说明与旧画像冲突时，先确认本次采用哪个约束。诊断本身只读。

**画出敞口。** 先写总资产和可用现金，再列前一大、前五大持仓、有效持仓数及行业、板块和资产类别占比。同一产业链的三只股票可能依赖同一批客户。把相同风险来源合并讨论，并标明哪些归类是研究判断。集中度的分母按工具定义，现金占比单列；缺价、停牌和限制卖出的仓位分别列出。

**用同一段历史比较。** 调用 `portfolio_risk(window_days=250, benchmark="000300.SH")`，需要时按用户的投资市场和期限更换基准与窗口。抄录有效观测数、年化波动、Beta、最大回撤、同期基准、最大的相关性组合和剔除清单。工具返回的小数比例转为百分数展示。估值覆盖的全簿与风险计算的子集分开列；缺少基准或历史行情时保留空项。静态持仓历史回放不能当成用户的真实收益。

**回到用钱的日期。** 如果半年后要付一笔确定款项，列出现金能覆盖多少、余款依赖哪些可变现持仓。若风险集中于同一行业，说明什么事件可能让这些持仓同时下跌。结尾给两到三个可执行的核对任务，例如确认一个停牌仓位的估值日、核一笔支出的到账时间。用户另行要求记账时再进入交易预览与确认流程，凭原成交编号去重。
